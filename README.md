# Student Hash Tables — Linear Probing and Double Hashing

A menu-driven C++ program that builds student hash tables, searches by student ID, and reports probing statistics for two collision-resolution strategies.

**Source:** `main.cpp`  
**Authors:** 劉至嘉 (11227205) and 楊碕萍 (11027214)

## Features

- **Linear probing:** resolves collisions by checking consecutive slots, wrapping at the end of the table.
- **Double hashing:** resolves collisions using a key-dependent step size calculated from a secondary prime value.
- **Shared hashing interface:** implements both strategies through the `OpenAddressingHashMap` base class.
- **Prime table capacity:** chooses a prime capacity at least as large as `ceil(record_count × 1.1)`.
- **Prime lookup optimization:** enables a compile-time lookup table for small prime candidates through `ENABLE_PRIME_NUMBER_LOOKUP_TABLE`.
- **Student ID lookup:** displays the matching ID, name, average score, and number of probes, or reports an unsuccessful lookup.
- **Probing statistics:** reports average successful-search comparisons for both strategies and average unsuccessful-search comparisons for linear probing.
- **Binary input preference:** loads an existing binary dataset first; if unavailable, reads the text dataset and creates a binary copy.
- **Table export:** writes every table slot, including empty slots, to a text report.
- **Menu validation:** reports invalid commands, missing datasets, and attempts to use double hashing before loading data.

## Menu

| Option | Action | Prerequisite |
| --- | --- | --- |
| `0` | Quit | None |
| `1` | Load records, build a linear-probing table, and search student IDs | An `input<N>.bin` or `input<N>.txt` file |
| `2` | Build a double-hashing table using the same records and search student IDs | Run option `1` first |

Enter `0` at a student ID prompt to return to the main menu. Enter `0` at the file-number prompt to cancel loading.

## Input Format

Place the input dataset in the working directory. Entering file number `1` makes the program try `input1.bin`, then `input1.txt` if the binary file is absent.

Text files contain one student per line, with nine tab-separated fields and **no header row**:

| Field position (1-based) | Meaning |
| --- | --- |
| `1` | Student ID |
| `2` | Student name |
| `3`–`8` | Six individual scores |
| `9` | Average score |

The six scores are stored as `uint8_t`; the supplied average is stored as a `float`. The program reads the average from the file rather than calculating it from the six scores.

IDs and names use fixed 10-byte character arrays. Keep each encoded value within nine bytes to retain a terminating null byte; the source does not enforce these limits. Multibyte characters consume more than one byte.

Binary files contain raw `Student` structures, including any compiler padding. Their layout depends on the compiler and platform; use a binary file generated by a compatible build.

## Generated Files

| Filename | Contents |
| --- | --- |
| `input<N>.bin` | Binary copy created when loading from text |
| `linear<N>.txt` | Linear-probing table with slot index, initial hash index, student ID, name, and average score |
| `double<N>.txt` | Double-hashing table with the same report fields |

Probe averages and interactive search results are printed to the console. Existing report files with the same names are overwritten.

## Typical Usage

1. Select `1` and enter the dataset number.
2. Search one or more student IDs; enter `0` to return to the menu.
3. Select `2` to build the double-hashing table from the same dataset.
4. Search IDs again and compare the console statistics and exported tables.
5. Select `0` at the main menu to exit.
